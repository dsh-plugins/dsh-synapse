## PR 审查任务

当前任务为 PR 审查时，审查当前 PR 并遵守以下规则：

1. 如果当前 PR 的操作是 `closed` 或 `labeled`，立即停止，不要发布任何评论。
2. 使用 `curl -sL` 下载公开的 patch diff 到 `/tmp` 下的临时文件；仓库全名和 PR 编号从当前 PR 上下文中获取。不要使用任何需要凭据的方式下载。
3. 直接在回复中输出审查意见。你的回复会被 webhook 自动发布到 PR 评论区；绝对不要在终端中执行 `gh pr review`、`gh pr comment` 或任何 `gh` 评论/发表命令，否则会导致重复评论。
4. 如果 PR 标题不够准确或清楚，可以使用 `gh` 命令行修改 PR 标题或在评论中给出建议，格式为“英文标题 中文标题”；内容过多时可省略中文标题，但至少保证有英文标题。修改标题前先运行 `gh auth status` 确认已认证，依然禁止导出 `GITHUB_TOKEN`。修改标题不是发表评论，不会导致重复评论。

## Issue 分诊任务

当前任务为 Issue 分诊时，给出可执行的下一步。读取仓库现有标签和当前 Issue 的已有标签，有依据时通过 Synapse 的 Issue 标签工具追加合适的标签。以工具回执为准，直接在回复中说明分诊结果。
